# 2026-10-29 MCP 真实数据输出类型修复

生产公网实测发现 MCP 本人课表、伙伴课表和宿舍洗衣工具在业务网关返回 HTTP 200 后，因输出契约不匹配而被官方 SDK 拒绝，客户端只能得到 JSON-RPC 错误。其余只读工具可用；同账号 GraphQL 的 23 项只读查询全部成功。

共享接口契约将两处课表 `arrangements[].teachingMethod` 标为可空字符串，匹配未知教学方式和自定义课程；洗衣 `devices[].floor` 改为可空整数，匹配服务端楼层解析的实际结果，包含负数地下楼层。MCP 继续严格校验并原样返回数据。OpenAPI、文档和 GraphQL 同步使用准确契约，GraphQL 的洗衣楼层由 `String` 更正为 `Int`。

增加官方 MCP 客户端回归测试，分别调用本人课表、伙伴课表与洗衣工具，覆盖教学方式字符串/null、楼层正整数/负整数/null，并核对业务数据无损返回；修复前三个场景均复现 SDK 输出校验错误。GraphQL 回归测试核对楼层保持数字/null。

本地完整 MySQL/Redis Go 测试、race 检测和 vet 通过；前端 27 项测试、类型检查、lint、格式检查和构建通过。本次不改变鉴权、权限、限流、额度或证明开具流程。

发布后以原生产有效学校身份复测全部 23 项只读工具和 GraphQL 查询，记录镜像、源码、CI 与 Flux 应用版本；不得把 HTTP 200 本身当作 MCP 成功。
